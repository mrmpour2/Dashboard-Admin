# SEC-005 — implementation for independent review

Local changes only. No production migration, actual SMS, actual refund, AI call,
remote push or release approval is authorized by this implementation.

## Discovery and behavior

`products.stock` was decremented in guest creation and in staff order creation.
Guest orders use `chat_orders`, `chat_order_items`, `chat_payments`; staff sales
use `orders`, `order_items`. Variants and add-ons share the product's inventory.
Payment methods currently implemented are Zibal and card-to-card. There is no
wallet/COD subsystem; wallet TTL is configured for a future adapter only.

`product_stock` now holds `on_hand` and `reserved`, with database checks. The
existing `products.stock` is a database-maintained available-stock projection so
the menu, assistant and admin use consistent availability. Staff inventory edits
retain their available-stock contract. No guest order consumes physical stock
before server verification. Staff-created orders are explicit recorded sales.

The stock service owns all product stock deductions. An active reservation has
a partial unique index on order kind/order/SKU. Guest phone/IP limits, idempotency
and stock updates use database locks and conditional SQL, not process memory.
The 15-minute TTL applies to online and card receipts; wallet TTL is 5 minutes.
User cancellation records `released`; expiry records `expired`.

Payment finalization checks stored amount/order identity, locks order before
reservation/SKU, consumes once and confirms the order. A late verified payment
re-reserves or queues an idempotent refund, notification and support ticket. A
late card receipt without inventory is rejected with a manual-review ticket.
Outbox deliveries require provider confirmation and retain failures for retry.
The provider must honor its stable idempotency key across crashes. Mock providers
are memory-only, opt-in in development/tests and prohibited in production.

Checkout requires a scoped HttpOnly OTP proof. OTP hashes use HMAC, expiry is five
minutes, resend is 60 seconds, five failures lock the code and a captcha provider
is required after three failures. Defaults fail closed until real adapters exist.
Audit rows are append-only by database trigger; DB owners/DDL remain a deployment
privilege boundary. Hashes, PINs, codes and cookies must never appear in logs.

## Migration, backfill and operational job

1. Review schema drift/history before deployment. The additive migration is
   `20261020010000_stock_reservations`; it does not infer historical stock data.
2. Keep checkout closed and inventory writers stopped during backfill.
3. `node scripts/backfill-stock.mjs` reports a dry run. `--apply` reconstructs
   `on_hand = current available + legacy unpaid holds` and creates their ledger.
   Repeated apply skips migrated records; inconsistent partial states abort.
   The script deliberately permits writes only to localhost:55439/elin_audit in
   this remediation. A production execution requires separately reviewed tooling.
4. Inspect dry-run job output, then turn `STOCK_JOB_DRY_RUN=false`. The server
   invokes release/outbox every 60 seconds; product reads lazily expire holds.
5. Move `STOCK_ROLLOUT_PERCENT` from 0 to 10, then 100 after review. Fallback is
   closed checkout; it never restores the vulnerable permanent-decrement path.
6. `/api/payment/stock-metrics` requires ADMIN/MANAGER and exposes expiry ratio,
   stock conflicts, verified-without-stock events, active phone/IP holds, pending
   deliveries and ledger reconciliation. A daily log must be compared with an
   independent physical warehouse count; this repo has no warehouse data source.

## Validation and evidence

`audit/evidence/open-risks.json` is the pre-change HTTP reproduction (2026-10-20).
`audit/evidence/sec005-tests.log` and `sec005-after.json` contain the dedicated
PostgreSQL lifecycle/real-concurrency tests. `sec005-regression.log` contains the
full suite, `sec005-types.log` the website typecheck, `sec005-website-build.log`
the bundle build, and `sec005-lint.log` the lint result. All use a disposable
database; migration SQL/checks/triggers are exercised rather than `db push`.
The full test command serializes fixture setup because Prisma's migration lock
is database-wide; tests inside each suite still exercise actual concurrency.

## Remaining release conditions

Connect and verify real SMS, captcha, refund and notification adapters separately;
do not enable mocks in production. Validate Zibal contracts against a sandbox,
especially previously-verified transactions (currently routed to a durable support
ticket unless the local payment is already finalized). Verify production proxy
trust, DB role permissions and warehouse reconciliation. A local implementation
and passing tests do not constitute independent verification. `release_gate.json`
continues to control release and has not been promoted by this work.
