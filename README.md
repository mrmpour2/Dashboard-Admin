# Nebula Admin — پنل مدیریت

پنل مدیریتی مدرن با React 19 (فرانت‌اند) و Express + PostgreSQL (بک‌اند)، با پالت رنگی اختصاصی، تم دارک/لایت، و انیمیشن‌های نرم.

```
dashboard/
├── frontend/   پنل کاربری (React + Vite + Tailwind v4)
└── backend/    API سرور (Express + Prisma + PostgreSQL)
```

---

## ۱) پیش‌نیازها

- **Node.js نسخه ۲۰ یا بالاتر** — [nodejs.org](https://nodejs.org)
- **PostgreSQL نسخه ۱۴ یا بالاتر** — می‌توانید محلی نصب کنید یا از یک سرویس ابری (Neon، Supabase، Railway و...) استفاده کنید.
- آشنایی پایه با خط فرمان (Terminal)

## ۲) راه‌اندازی بک‌اند

```bash
cd backend
npm install
cp .env.example .env
```

فایل `.env` را باز کنید و مقادیر زیر را با اطلاعات واقعی خودتان جایگزین کنید:

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | آدرس اتصال به PostgreSQL شما |
| `CORS_ORIGIN` | آدرس فرانت‌اند (پیش‌فرض: `http://localhost:5173`) |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | دو رشته تصادفی و مجزا. برای ساخت یکی از این دستورها استفاده کنید: |

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

سپس دیتابیس را آماده کنید:

```bash
npm run prisma:generate    # ساخت Prisma Client
npm run prisma:migrate     # ساخت جدول‌ها در دیتابیس
npm run seed                # (اختیاری) افزودن داده‌های نمونه برای تست
```

> دستور `seed` یک کاربر ادمین نمونه می‌سازد:
> **ایمیل:** `admin@nebula.local` — **رمز عبور:** `Passw0rd!`
> ⚠️ حتماً بعد از اولین ورود در محیط واقعی (production) این کاربر را حذف یا رمزش را عوض کنید.

در نهایت سرور را اجرا کنید:

```bash
npm run dev       # حالت توسعه (با ری‌استارت خودکار)
# یا
npm start         # حالت عادی
```

سرور روی آدرس `http://localhost:4000` بالا می‌آید. برای بررسی سلامت سرور:

```bash
curl http://localhost:4000/api/health
```

## ۳) راه‌اندازی فرانت‌اند

در یک ترمینال جداگانه:

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

فرانت‌اند روی `http://localhost:5173` بالا می‌آید و به‌صورت خودکار درخواست‌های `/api` را به بک‌اند (پورت ۴۰۰۰) پروکسی می‌کند.

برای ساخت نسخه نهایی (production build):

```bash
npm run build     # خروجی در پوشه dist/
npm run preview   # پیش‌نمایش نسخه build شده
```

## ۴) ساختار پروژه و معماری

### فرانت‌اند
```
frontend/src/
├── app/            نقطه ورود و مسیریابی (React Router)
├── components/ui/  کیت کامپوننت مشترک (Button، Card، Dialog، Table، Toast و...)
├── features/       صفحات اصلی (Home، Users، Products، Tickets، Comments)
├── layouts/         چیدمان کلی (Sidebar، TopBar، Theme دارک/لایت)
├── services/        اتصال به API (axios با تمدید خودکار توکن)
├── hooks/           هوک‌های مشترک
└── styles/          توکن‌های رنگ و تم (input.css)
```

هر کامپوننت UI از **توکن‌های رنگی معنایی** (`bg-Surface`, `text-textPrimary`, ...) استفاده می‌کند نه رنگ‌های ثابت Tailwind — به همین دلیل تغییر تم دارک/لایت به‌صورت خودکار در کل پروژه اعمال می‌شود.

### بک‌اند
```
backend/src/
├── config/       تنظیمات (env، دیتابیس، لاگر)
├── middleware/   احراز هویت، محدودیت نرخ درخواست، اعتبارسنجی، مدیریت خطا
├── routes/       تعریف مسیرهای API
├── controllers/  لایه HTTP (دریافت request، ارسال response)
├── services/     منطق اصلی برنامه (business logic)
├── validators/   قوانین اعتبارسنجی Zod برای هر endpoint
└── utils/        ابزارهای مشترک (JWT، هش رمز عبور، خطاهای سفارشی)
```

الگوی هر ماژول: **route → validate → controller → service → prisma**. برای افزودن یک منبع (resource) جدید، از پوشه `users` به‌عنوان نمونه استفاده کنید.

## ۵) نکات امنیتی که رعایت شده

- **رمز عبور** با bcrypt (۱۲ دور) هش می‌شود؛ هرگز متن خام ذخیره نمی‌شود.
- **توکن دسترسی (access token)** کوتاه‌مدت (۱۵ دقیقه) است و فقط در حافظه مرورگر نگه‌داری می‌شود (نه localStorage) — کاهش ریسک سرقت توکن از طریق XSS.
- **توکن تمدید (refresh token)** در کوکی `httpOnly` + `secure` + `sameSite=strict` ذخیره می‌شود (جاوااسکریپت اصلاً به آن دسترسی ندارد) و نسخه هش‌شده‌اش در دیتابیس است تا در صورت نیاز قابل ابطال باشد. با هر تمدید، توکن قبلی باطل و توکن جدید صادر می‌شود (rotation).
- **Rate limiting** جداگانه و سخت‌گیرانه‌تر روی مسیرهای ورود/ثبت‌نام (مقابله با brute-force).
- **Helmet** با سیاست امنیتی محتوا (CSP) فعال است.
- **CORS** فقط به origin(های) مشخص‌شده در `.env` اجازه دسترسی می‌دهد.
- **HPP** از آلودگی پارامترهای HTTP جلوگیری می‌کند.
- پیام خطای ورود برای «کاربر یافت نشد» و «رمز اشتباه» **یکسان** است تا مهاجم نتواند ایمیل‌های معتبر را حدس بزند (جلوگیری از user enumeration).
- کاربران نمی‌توانند نقش یا وضعیت حساب خودشان را تغییر دهند یا خودشان را حذف کنند.
- در production، پیام‌های خطای داخلی و stack trace هرگز به کاربر نمایش داده نمی‌شود؛ فقط در لاگ سرور ثبت می‌شود.
- هیچ داده حساسی (رمز، توکن، هدر Authorization) در لاگ‌ها ثبت نمی‌شود.

## ⚠️ محدودیت این تحویل — مهم بخوانید

بک‌اند در محیطی نوشته و بازبینی شد که دسترسی شبکه‌اش محدود بود و **اجازه دانلود باینری موتور Prisma را نمی‌داد** (این باینری از هر نصب Node.js دیگری معمولاً بدون مشکل دانلود می‌شود). به همین دلیل:

✅ **تست و تأیید شد:**
- تمام فایل‌ها از نظر نحوی (syntax) بدون خطا
- تمام قوانین اعتبارسنجی Zod با داده‌های واقعی (معتبر و نامعتبر)
- توابع JWT و هش رمز عبور به‌صورت مستقل (round-trip کامل)
- کل اپلیکیشن Express با یک Prisma Client موقتاً شبیه‌سازی‌شده بالا آمد و رفتار واقعی HTTP آن (احراز هویت، CORS، Rate limiting، مدیریت خطا) با درخواست‌های واقعی تست شد

❌ **تست نشد** (چون نیاز به اتصال واقعی دیتابیس با موتور Prisma داشت):
- عملکرد واقعی کوئری‌های Prisma روی PostgreSQL
- سناریوی کامل ثبت‌نام → ورود → تمدید توکن → خروج با دیتابیس واقعی

**توصیه:** پیش از استفاده در production، حتماً مراحل بخش «راه‌اندازی بک‌اند» را روی سیستم خودتان اجرا کنید و سناریوهای اصلی (ثبت‌نام، ورود، ساخت/ویرایش/حذف کاربر و محصول) را دستی یا با ابزاری مثل Postman تست کنید.

## ۶) دستورات مفید

| دستور | محل اجرا | توضیح |
|---|---|---|
| `npm run dev` | frontend یا backend | اجرای حالت توسعه |
| `npm run build` | frontend | ساخت نسخه نهایی |

| `npm run seed` | backend | افزودن داده‌های نمونه |
